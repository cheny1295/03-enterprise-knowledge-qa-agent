# 07 设计覆盖与待验证问题

本文保留资料调研中影响当前交付的决策，不重复逐轮搜集过程。参考来源见
[开源架构参考摘要](06-open-source-reference-survey.md)，详细接口以
[架构文档](../架构文档/README.md)为准，实际运行结论以
[评估记录](03-evaluation.md)为准。

## 1. 覆盖口径

将题目要求拆为“问题 → 设计落点 → 验证材料 → 剩余限制”，不以搜集到资料或写出设计
代替实现验收。当前目标是交付可运行、可回查的离线核心，而不是承诺完整企业平台。

## 2. 核心问题覆盖

| 问题域 | 设计落点 | 当前证据与剩余限制 |
|---|---|---|
| 输入与上下文 | 请求校验；用户历史补足指代；历史助手文本不作为证据 | 最小示例 `05-history`；自然语言条件自动确认未实现 |
| 意图与三路回复 | 非事实快答、事实 FAQ、深层查询、按原因兜底 | 离线路由与 FAQ 有历史局部记录；不提供真实意图准确率 |
| 身份与租户 | 可信身份确定 TenantContext；模型不能切换 tenant | 身份/隔离有历史局部记录；未实现生产认证平台 |
| 资料一致性 | 每次知识请求绑定一次只读快照，Search/Read 共用 | 本地契约与替身发布记录；真实 Qdrant 和跨进程发布未验收 |
| 检索与向量库 | fixture 作为离线入口；Qdrant/CUDA + 词项混合召回作为显式可选运行模式 | 已有适配器和替身接线记录；真实向量召回未运行 |
| 引用与证据 | `SearchCandidate → ReadEvidence → Claim/Citation` | 聚焦测试覆盖原文回查和 30→45 天变更；不证明通用语义蕴含 |
| 资料冲突 | 保存双方证据；仅按显式范围、替代或优先级裁决 | `02-conflict` 及历史局部测试；未实现通用语义冲突裁决 |
| 决策与预算 | 动作/观察循环；分类与决策共用模型预算；工具独立计数 | 正常/冲突 Trace 和预算聚焦测试；Mock 不证明真实 LLM ReAct |
| 失败与兜底 | 工具错误、资料不足、预算耗尽分别表达 | `03-outside`、`06-tool-failure`；真实 provider 网络失败未验证 |
| 工具与内容安全 | Search/Read 白名单；检索文本不能扩大权限 | 本地动作校验与授权设计；没有生产红队或安全认证结论 |
| 可观测性 | 同次运行生成 input/output/Trace，以请求 ID 关联 | 六组最小材料和 `summary.json`；不保存内部思维链 |
| 提交与复现 | 标准库入口、可复制命令、AI 使用说明、约 5 小时记录 | 提交区已运行六场景和三项聚焦测试；GitHub 信息待补 |

## 3. 关键设计取舍

### 不用框架名称代替架构解释

原生 Python 足以表达当前单 Agent 的有限循环；分层、状态和契约必须能直接对应实现。
复杂工作流、分布式编排和管理后台不纳入首版。

### 不让快答绕过证据

非事实问候可用模板结束；事实 FAQ 仍须 Search/Read 和结果校验。遇到冲突、缺条件、
未读候选或覆盖不足，应升级查询或明确缺口，不能为了快而输出未经核对的制度结论。

### 不让模型替代权限与规则

租户由可信入口提供，不能从问题正文推断；制度优先级来自原始资料的明确字段，
不能由相似度、文件顺序或日期新旧决定。

### 不把所有失败都改成“暂无资料”

资料不足提示补充来源；冲突提示确认条件；工具失败保留诊断；预算耗尽明确未完成。
这些状态分别有不同的下一步动作，统一包装反而降低可用性。

## 4. 后续工作排序

1. **真实模型闭环**：接入可用 provider，验证结构化动作解析，并保存不同观察下的真实决策记录；
2. **真实检索链**：固定 embedding revision，在 CUDA 上编码并执行 Qdrant 写入、查询和删除；
3. **语义质量评估**：扩大合成资料，评估改写召回、冲突识别和主张支持度；
4. **生命周期验证**：补充真实后端的发布、重启、撤权和删除传播验证。

新的失败样例先定位到输入、检索、证据、决策或执行层，再决定是否需要查资料或修改设计。
没有明确失败或需求变化时，不继续堆积参考项目，也不以生产能力清单扩大首版范围。
