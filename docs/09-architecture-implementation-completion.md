## 状态

已核对真实源文件，确认本轮修复范围：

- AskRequest 缺少明确过滤入口；增加显式 `filters` / `historical`，不让模型自行猜测过滤范围。
- 指代规范化应在分类前完成，支持有用户对象背景的裸追问，不引用历史 assistant 答案。
- 明确替代/优先级应能选择适用来源，同时保留关系双方引用；只有日期较新仍不得选赢家。
- completed 不能忽略未读候选、已知截断或未恢复工具失败；无关成功不能清除失败。
- 擦除需持久阻断旧 READY 再发布，并支持失败后重启续清理；发布文件/内存切换先完成同一套校验。
- CLI 启动配置错误需输出经 ResultValidator 校验的安全错误信封。

已新增并执行上述缺口的聚焦局部用例，实际结果见下文。未执行完整架构验收矩阵。

## 本轮已落地

- `service.validate_request` 接受并校验 `filters`、`historical`；应用默认 `status=["active"]`，撤回制度必须同时明确历史模式和 `effective_on`，请求来源写入 `filters_confirmed` Trace。
- `routing.prepare_route` 在意图分类前补充用户历史中的最近明确对象；只使用历史 user 消息，历史 assistant 文本不进入制度证据。
- `retrieval` 保留完整词项分支长度并传递截断事实；显式 `supersedes`/同范围 `priority` 可由 OfflineModel 选择适用来源，关系双方仍保留为 citations。
- `AgentState.unrecovered_errors` 按操作键跟踪失败，`ResultAssembler` 拒绝未恢复错误、未读候选和截断召回的 completed。
- 发布前阻断清单、擦除进度 `erase.json` 和替代快照发布顺序已落地；向量/原文清理失败可在下一次管理调用续做，问答入口不会读取阻断旧包。
- CLI provider/身份/配置启动错误现在转换为统一、无租户正文的 `AnswerResult`；管理 CLI 仍返回结构化错误 JSON。
