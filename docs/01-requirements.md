# 01 需求与成功标准

## 1. 用户、目标与选题

选题为“企业知识问答 Agent”。目标是帮助企业员工在当前租户已发布的制度或 FAQ
中找到可靠答案，并明确展示答案依据、资料缺口和任务状态。

输入包括：

- 当前问题；
- 可选对话历史；
- 由可信调用方确认的检索过滤条件；
- 租户和主体身份。

其中问题、历史和过滤条件是请求字段；主体与租户由可信入口单独提供，不接受模型
或用户文本自行切换身份。

资料至少包含租户、文档 ID、版本日期、章节定位、原文和适用范围。

## 2. 交付结果

每次请求输出：

- `answer`：面向用户的回答；
- `citations`：文档 ID、版本、章节和可回查的原文片段；
- `gaps`：资料缺口或需要用户确认的条件；
- `status`：任务状态；
- `trace_id`：对应 Trace；
- 必要时输出冲突评估、错误码和停止原因。

## 3. 必须覆盖的路径

1. **浅层非事实路径**：纯问候或能力询问使用边界模板，不加载事实资料。
2. **明确事实/FAQ 路径**：仍执行 `Search → Read → Finish`，不能直接使用 snippet
   或 FAQ 元数据作为制度答案。
3. **深层查询路径**：根据 Observation 选择补充检索、读取其他候选、追问或结束。
4. **兜底路径**：区分资料不足、冲突、工具失败、模型协议错误、权限拒绝和预算耗尽。

## 4. 题目六项验收

- 明确答案；
- 文档冲突；
- 资料外问题；
- 改写后的相似问题；
- 上下文追问；
- 工具失败。

## 5. 不可退让约束

- `tenant_id` 只能来自可信 `TenantContext`；
- Search 只能产生 `SearchCandidate`，授权 Read 才能产生 `ReadEvidence`；
- 事实答案必须能从 Evidence 回查到当前快照原文；
- D01 的 30 天和 D02 的 15 天未决时必须保留双方引用并请求确认；
- 模型步骤、工具调用和 embedding 查询均受预算约束；
- 模型只能调用白名单中的 `search_documents` 和 `read_document`；
- 工具错误不能伪装成资料不足或正常完成。

## 6. 可验证成功标准

当前交付版本的成功标准是：标准库离线 Mock 可以运行，六类场景有实际输入、输出和
Trace，Trace 能展示观察驱动的路径差异，局部测试验证引用回查、原文变化和预算上限。
真实业务资料、真实模型、CUDA、Qdrant 和 provider 的运行证据不在本次离线验证范围内，
已在评估文档中单独列明。
